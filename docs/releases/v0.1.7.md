## Implemented scope

The first independently shippable slice is [X1](../machine-interface-spec.md#diagnostics)
for `check` and `run`. `--format=json` produces one UTF-8 `qleisli.result`
version-1 object and LF on stdout, including handled errors. Diagnostics retain
their category, optional original-source byte span, Unicode scalar coordinates
and project-relative or bundled identity. Exit codes remain 0/1/2 for success,
failure and usage. Handled JSON results leave stderr empty; write failure exits
1 and reports on stderr. Successful `run` returns the finite reference
distribution in lexicographic bit-vector order, not samples.

Additive structured frontend entry points share the existing compilation and
independent verification path. The loader retains parser provenance and source
coordinates before dropping its source snapshot. No human diagnostic prose is
parsed to recover error categories. Existing `CompileError`, `ErrorCode`,
`ProjectError`, source/IR checking and human result rendering remain in place.

## Compatibility and remaining work

- No new `.qli` syntax, stdlib definition, IR variant, verifier/evidence rule,
  dependency, capacity or minimum toolchain. Lean/Mathlib remain 4.30.0;
  Physlib remains deferred. JSON records confer no extra semantic evidence.
- JSON flags may occur before/after positionals. Duplicate/unknown flags and
  missing values are usage errors. Use `./` for a path starting with `-`.
  JSON mode requires UTF-8 identities; legacy human mode still supports its
  existing OS paths. Missing source locations are null, never fabricated spans.
- `doc` remains Markdown-only. `sample`, `emit-ir` and `verify-ir` remain
  unimplemented and return usage errors; a JSON request still gets a JSON error.
  N1–N6, X2–X6 and M2 remain open. The initial X1 work does not complete M1.
- JSON probability endpoints clamp only roundoff within 2^-40; nonfinite or
  materially out-of-range values reject atomically as `numerical`. This does
  not change the reference simulator or establish an exact probability theorem.

## M1.1-A connection continuation

The user additionally requested OpenQASM 3/QIR connections as M1.1 on
2026-09-28. This continues the same 0.1.7 development exception; it neither
completes M1 nor creates a new release. The earlier X1 validation table above
is preserved as that slice's history.

Implemented the [terminal connection contract](../interop-m1.1.md) in the
additive `qleisli_core::interop` module, with OpenQASM 3 import/export and
QIR 2.0 Base textual output. The subset has fixed registers, twelve exact
gates, explicit fresh initialization and terminal observation. Import rebuilds
logical ownership and uses the existing independent verifier. Export accepts
only a stated subset of already verified IR, preserving gate phases, operand
axes and declared result order. No new `.qli` form, public core IR variant,
checker/evidence rule, runtime dependency or existing capacity was changed.

OpenQASM declarations leave quantum state undefined; importing them as zero
without a preparation requirement would change semantics. Therefore every
qubit needs exactly one initial `reset`, and QASM export writes the reset
prefix. Intermediate resets, measured-qubit reuse, unsupported angles, gate
modifiers, user gate bodies and external includes are rejected. Hidden terminal
results trace out through observing discard; they never grant pure cleanup.

The [host example](../../examples/interop.rs) supports QASM checking, exhaustive
reference distributions, canonical QASM and QIR output, plus `.qli` project
export. It returns no partial artifact on failure. Main CLI commands and the
X1 JSON schema are unchanged. New bounds are 12 qubits/results, 4,096 gates,
1 MiB QASM, 65,536 QASM tokens and 65,536 visited raw operations.
