# Qleisli 0.2.0: authoring ergonomics

Status: **development version; implemented and locally validated** (2026-09-28,
JST). The user requested authoring issues 1–3: product patterns in basis
parameters, n-ary tuples and precise dropped-owner locations. Type/size
parameters and cross-interface QPE reuse are explicitly deferred. The selected
version follows the [compatibility policy](../versioning.md): changing the
public Rust `Param` AST requires MINOR. Branch:
`codex/v0.2.0-authoring-ergonomics`, continuing `f4a338d`.

The untagged 0.1.8 checkpoint is included, with its
[operation-parameter and corpus evidence](v0.1.8.md) preserved. This record
does not publish either version. The six imaginary algorithm drafts and their
requirement/review records already satisfy the initial-draft prerequisite for
0.2.0; their syntax is not thereby implemented or proved.

## Delivered source behavior and checking boundary

- `basis fn phase((a,b):(Bit,Bit))->(Bit,(Bit,Bit)){(0,(0,a and b))}` can state
  an independent nonconstant pair meaning. Name, wildcard and nested product
  patterns reuse the existing finite basis binding rules; all parameter names
  must be distinct. One pattern is one argument; every component, including
  ignored bits and Unit nodes, stays in the function's domain.
- Types, ordinary/basis values and patterns accept tuples with at least two
  fields, left-folded to existing binary pairs. `(a,b,c)` is `((a,b),c)`;
  explicit right/balanced trees remain distinct. Evaluation order, effects,
  output leaf order, linear ownership and phase are unchanged. No implicit
  function argument packing, singleton tuples, trailing commas or ordinary
  function parameter patterns are added. Flat/mixed syntax respects the
  original AST depth limit.
- Unreturned quantum owners point to the actual parameter, local binding or
  computed-region binder, including tuple components and shadowed names.
  Error categories, JSON schema and ownership acceptance are unchanged.

The [normative grammar](../syntax-v0.md#authoring-forms-added-in-product-020)
and [language rules](../language-spec.md) specify these language forms.
Examples and [source regressions](../../tests/fixtures/ergonomics/README.md)
include independently checked phase/permutation targets and intentional
failures. No new core IR variant, gate, verifier rule, evidence authority,
bundled stdlib API or dependency is introduced. Existing finite tables and
exact evidence check the result; full frontend adequacy remains open.

## Migration

From the 0.1.8 development AST, replace `Param { name, ty, span }` by
`Param { pattern: Pattern { span: name.span, kind: PatternKind::Name(name) },
ty, span }` for ordinary names. AST readers must handle `param.pattern`;
basis parameters can also use tuple/wildcard patterns. `TypeKind`,
`PatternKind` and both expression kinds still use binary tuple variants.
No source keyword is newly reserved by this continuation. Existing accepted
binary `.qli` programs keep their types and behavior; error locations improve.
Migration from published 0.1.7 also includes the
[inherited M1 reserved-name and AST changes](v0.1.8.md#compatibility-and-migration).

`phase_by` still requires **`(Bit,(Bit,Bit))`** as its exponent result type;
flat `(Bit,Bit,Bit)` is a different left-associated tree. Likewise, n-ary sugar
does not make a left-associated four-bit register interchangeable with the
balanced modular-arithmetic interface.

The full suite initially found an old scope regression asserting that a leak
points at the entire block. It now asserts the exact shadowing binder, keeping
the original ownership rejection. Both complete runs above follow this fix.
Prior 0.1.8 results retain their original scope. No new general source,
algorithm or Lean proof is claimed.

Hosted CI/Linux execution, new distribution/package builds, the unchanged
research package and external OpenQASM/LLVM validators were not rerun here.
No new dependency or toolchain requirement was introduced.

## Remaining work and publication

LLM authoring ergonomics remain a development priority, assessed with actual
source and semantic regressions rather than prose or model identity. Generic
type/size parameters, the finite-template/R14 ordering decision, gate-provider
uniformity, general Shor/QPE sharing and V1-C1–C5 remain future work. Neither a
comparative LLM benchmark nor a scalable checking claim follows from this work.
No tag, push, hosted release or registry publication is performed.
