## Status

Surface-language design issue for **Qleisli 0.3.0**.

**Completion status (2026-11-13): the eight original criteria are verified for the documented initial finite-ADT profile.** PR #429 merged only a validated foundation checkpoint. Its unintended automatic closure was reversed; no criterion or beta completion credit was awarded.

This issue defines finite algebraic data types as part of the **ordinary finite type universe `T`**. It does not introduce a second quantum ADT hierarchy.

## Adopted type-theory alignment

Under the 0.3.0 type model:

```text
T       ordinary value
Q<T>    quantum ownership over T
```

Therefore, if a finite enum is admitted as an ordinary finite type:

```qli
enum Pauli {
    I,
    X,
    Y,
    Z,
}
```

then both of these are meaningful in principle:

```text
Pauli
Q<Pauli>
```

No separate `QEnum`, `CEnum`, or quantum-sum type constructor is required merely to place the finite basis under quantum ownership.

## Ordinary `match`

Ordinary `match` remains ordinary classical/static pattern selection:

```qli
match p {
    Pauli::I => ...,
    Pauli::X => ...,
    Pauli::Y => ...,
    Pauli::Z => ...,
}
```

where `p : Pauli` is an ordinary value.

The initial ADT surface may lower to a canonical finite tag representation.

## Quantum boundary: `Q<Enum>` is allowed; ordinary `match` is not

The previous wording suggested that `Q<Enum>` itself required a separate quantum-sum design.

That is superseded by the adopted `T / Q<T>` model.

The correct boundary is:

```text
p  : Pauli       -> ordinary match may inspect p
qp : Q<Pauli>    -> ordinary match must not inspect qp
```

A coherent selector uses the separate construct defined by #195:

```qli
qmatch(selector, target) {
    Pauli::I => U0,
    Pauli::X => U1,
    Pauli::Y => U2,
    Pauli::Z => U3,
}
```

subject to the final `qmatch` pattern policy.

Thus:

> **The enum type is ordinary. Quantum ownership is supplied by `Q<...>`. Classical inspection and coherent control remain different operations.**

## What 0.3.0 fixes

0.3.0 should fix only the semantic laws:

- finite ADTs are ordinary finite types;
- ordinary `match` acts on ordinary/static values;
- `Q<ADT>` is the ordinary application of the quantum ownership constructor;
- ordinary pattern matching cannot inspect a live `Q<ADT>`;
- coherent basis-space selection uses `qmatch`;
- no pattern syntax may create implicit measurement.

## What moves to 0.4.0

Detailed boundary ergonomics belong to #197, including:

- which enum/product patterns `qmatch` accepts;
- wildcard/complement arms;
- range/set patterns;
- canonical tag ordering and representation conveniences;
- pattern reuse between `match` and `qmatch`;
- implicit coherence around nested products.

0.3.0 need not freeze those conveniences.

## Initial ordinary ADT profile

Candidate 0.3.0 scope remains deliberately finite:

- finite fieldless enums;
- finite product/record sugar whose fields are ordinary finite types;
- optionally finite tagged payload variants with statically known representation;
- exhaustive ordinary `match` over static/runtime classical values;
- recursive/open/extensible ADTs deferred.

The exact surface breadth can remain conservative as long as the semantic classification above is preserved.

## Lowering principles

For ordinary values:

```text
finite enum
    ↓
canonical finite representation

ordinary match
    ↓
static selection or classical branch
```

For quantum-owned values:

```text
Q<finite enum>
    ↓
ordinary quantum ownership over that finite basis

qmatch
    ↓
coherent basis-space control
```

No lowering may turn `Q<Enum>` into an ordinary discriminant read.

## Non-goals

- no implicit measurement;
- no ordinary `match` on live `Q<T>`;
- no separate classical `C<Enum>` hierarchy;
- no separate quantum enum constructor;
- no recursive heap data structures or garbage collection in the initial profile;
- no open variants;
- no claim that every classical sum-type operation automatically has a coherent analogue.

### Ordinary source and type identity

Use nonempty finite fieldless enums and finite named records whose fields are ordinary finite types as the initial profile. Optional tagged payloads and recursive/open ADTs remain outside this initial surface as already permitted above. A singleton enum or an empty record has one basis value; it is distinct from Unit and Bits<0>, even when its quantum owner has no wires. No empty carrier is silently replaced by Unit.

Proposed forms retain Rust-like names and explicit constructors:

```qli
pub enum Pauli { I, X, Y, Z }

classical fn is_x(p: Pauli) -> Bit {
    match p {
        Pauli::I => 0,
        Pauli::X => 1,
        Pauli::Y => 0,
        Pauli::Z => 0,
    }
}
```

These examples are design inputs, not current executable APIs. Constructors/patterns resolve to original canonical type and variant declarations. Private access, duplicate declarations/fields/variants, ambiguous paths and wrong categories reject; no fallback by width or spelling. Record identity includes its declaration, ordered fields and complete field type trees. Distinct enums/records and equal-width Unit/Bit/Bits/product types do not become definitionally equal.

Ordinary match inspects only ordinary data and executes one arm. It uses the existing branch effect/ownership-frame rules; it may not inspect Q<T> or insert measurement/coherent control. Initially use exact finite labels with disjoint exhaustive arms. Constructor/closed-expression selection does not add general const<T> bindings or revive excluded #63. The existing Nat static language and #39 exclusion stay unchanged. Rich patterns, wildcard/complement conveniences and implicit coherence remain #197 work.

### Logical cardinality and physical code are separate

Support the three-variant case as a real finite carrier, rather than declaring every non-power-of-two enum to be Bits<N>. Preserve an enum's logical cardinality and nominal tree separately from its physical bit layout. A deterministic initial ordinal encoding may follow retained declaration order; this is a toolchain-bound implementation representation, not a new permanent external serialization ABI or adoption of #197 conveniences.

For a three-element carrier, the canonical example is E: C^3 -> C^4 with E|j> = |j> for j=0,1,2. Physical label3 is outside the image. Products/records use ordered component encodings; they do not infer tuple reassociation, separability or an implicit quantum-owner split. Sources, type descriptors, member/field order and encoding coordinates belong to dependency/evidence/cache identity, including type references appearing only in signatures or host bindings.

An implementation must independently establish the relevant code-space and actual-body equations, schematically:

```text
E_in† E_in = I
E_out† E_out = I
actualPhysicalBody * E_in = E_out * logicalBody
```

An explicit Meaning supplies a separate required logical map; a producer matrix, valid physical IR or matching probabilities cannot replace its actual-body/dependency/type/phase binding. Without an independent algorithm request, report only the actual checked typing/code-space scope. All-input/reference obligations and existing proof gaps stay explicit.

Logical effects must use logical cardinalities and actual purity. A physical 4x4 unitary body cannot make a logical 3->4 map Unitary: that map can at most be Isometry, after its own exact check. A left inverse on the three-state code cannot grant a whole-space inverse/control API. Retain both ports, exact interface conditions, explicit access evidence and inverse implementation requirements. Observation/reset/discard cannot be hidden by an encoding or a pure label. Unsupported coefficient/type/transport profiles refuse explicitly.

Reuse the common source judgment, ordinary project and selected Raw routes, original body/dependency reconstruction and existing native checks. Extend logical-carrier/encoding checking at the Lean boundary; do not create Rust acceptance or an erasing fallback to Bits<N>. Keep old physical Raw representations and admitted ownership/scope meanings intact where possible. Any required internal format change is explicit, versioned and fail-closed; no unbound external schema is enabled. Retain the existing source/tree/work/matrix/width capacities without raising them.
