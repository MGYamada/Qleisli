## Changes and compatibility

- Repair silent `zip` truncation in the auxiliary imaginary-design matrix
  helpers. Require nonempty rectangular inputs and compatible dimensions,
  reporting `ValueError` before arithmetic or comparison. Adjoint, scaling,
  identity and powers follow the same valid-matrix boundary. Invalid `close`
  calls raise even in negative examples.
- Reject NaN/infinity in either comparison operand, including complex
  components, and validate dimensions throughout the separate exact helpers.
  Add 29 helper regressions in total and run both suites in documentation CI. All existing
  52 mathematical checks remain unchanged and pass with the stricter helpers.
- Verify the six-draft review and record dense logical-matrix composition as
  an architectural blocker for size generalization. Clarify the required
  symbolic meaning/encoding/evidence boundary and the first generalized QPE
  angle/checking decisions in the [requirements index](../imaginary-v1/requirements.md).
- Adopt the subsequent requested research goal: design the complete
  [meaning/implementation boundary](../symbolic-contract-architecture.md)
  from first principles and start an independent implementation. Separate
  resource validity, semantic realization, actual entry establishment and
  algorithm claims; preserve exact phase and arbitrary-reference reasoning.
- Add the non-published [semantic-kernel prototype](../../research/semantic-kernel/README.md):
  typed symbolic meanings and encodings, shared proof DAGs, bounded exact
  leaves, explicit requested contracts, and independent binding to a limited
  actual raw-IR profile. A 128-bit raw local-Z example uses a 2-by-2 maximum
  leaf matrix and symbolic framing, not a global matrix.
- Add 20 general Lean semantic lemmas with explicit premises: composition,
  tensor/reference extension, qualified adjoint, control, and zero return.
  The limited derivation-soundness theorem assumes leaf soundness; it does
  not prove the Rust kernel, importer or complete compiler correct.
- Retain the design, prototype and regressions while deferring further
  symbolic-kernel development and production integration to future roadmap work.
- Record the quantum-library investigation and add Physlib's compatible
  `v4.30.0` revision to the Lean environment. Pin its full commit and transitive
  dependencies, preserve Lean/Mathlib 4.30.0, and separately audit eight selected
  external declarations. See the [dependency record](../physlib-environment.md).

The production Rust implementation, accepted `.qli` programs, existing public
syntax/APIs/IR/evidence, bundled definitions, effects, ownership, phase/layout
semantics, capacity and minimum toolchains are unchanged. Existing Lean
declarations are preserved; the new module contains supporting mathematics.
The separate research package has `publish=false` and adds only a path
dependency on this repository. The Lean environment adds Physlib and its inherited
documentation dependencies; Rust dependencies, existing dependency revisions and
Qleisli's license remain unchanged. Third-party licenses are recorded separately.
No source migration is needed. Empty helper matrices were not
supported mathematical fixtures; `Q<Unit>` still has dimension one.

The production finite checker still composes dense logical operators and
encodings. The research checker demonstrates composition without global
matrices in its stated profile; **it is not integrated into production source
acceptance, execution or auxiliary release**. New production functionality
requires a minor release under the version policy. Source correspondence,
entry establishment, final transformation evidence, parameterized algorithm
proofs, instruments and QPE angle/error decisions remain open. The initial
imaginary-v1 corpus prerequisite is satisfied; V1-C1–C5 and general
implementation soundness remain incomplete.

## Review follow-up

The subsequent full-codebase review identified two auxiliary-checker defects.
These fixes and the scheduling decision were initially recorded under `Unreleased`
and are included in the final 0.1.3 contents. Both project versions remain 0.1.3.

- `close([[0.0, float("nan")]], [[0.0, 0.0]])` previously returned `True`.
  Comparisons now reject NaN and infinity in either operand, including either
  complex component, with `ValueError`. This also prevents invalid values from
  making a negative mathematical check pass. Finite comparison tolerance is
  unchanged.
- The exact-example helpers still truncated malformed shapes:
  `subtract([[1, 0], [0, 1]], [[1]])` returned `[[0]]`, and transpose/multiply
  could ignore ragged entries. All matrix inputs now require nonempty
  rectangular shapes, subtraction requires equal shapes, and multiplication
  requires compatible inner dimensions. Control requires a square matrix,
  norms require column vectors, and constructors reject invalid dimensions.
  Rational and quadratic arithmetic remain exact; scalar matrices are 1-by-1.
- Further symbolic-kernel development and production integration are
  [future roadmap work](../../ROADMAP.md#future-work-symbolic-semantic-kernel).
  The existing design, prototype and regressions are retained. No target
  release is selected and production dense composition is unchanged.

Scoped local validation on 2026-09-27: 43 Python tests passed (18 imaginary
helper tests, 11 exact-helper tests, 14 documentation-checker tests), including
15 added regressions. The new rejection tests fail against the pre-fix helper
implementations. All 52 imaginary mathematical checks and 39 exact assertions
passed. Documentation references and `git diff --check` are checked for this
follow-up. Documentation CI now runs the exact helper suite and its fixtures.

No Rust or Lean source was changed in this follow-up, and their suites were
not rerun for it. Earlier Rust/Lean results above retain their original scope.
The earlier candidate archives predate these fixes. This historical follow-up did not refresh packaging,
create a commit/tag, or publish a release.
