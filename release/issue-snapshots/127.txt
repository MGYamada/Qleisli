## Three-theorem design alignment — 2026-10-08

**Maintainer-level design direction only.** This is not a new binding Constitution Guardian Office interpretation, constitutional amendment, theorem discharge, or guarantee-ledger admission. Existing ratified Constitution (#129), jurisdiction framework (#139), ledger (#135), and EXACT-2026-01 (#311) retain authority.

1. **QS / Soundness:** semantic acceptance proves the specified exact owner/access/effect/phase/meaning contracts, including clean return and dirty identity restoration. Ending `excl` restores *access authority* over the changed, still-live owner, not its prior state, and does not release it (#29/#70/#72/#157).
2. **PR / Physical Realizability:** separately admitted, independently checked target realization implements the accepted semantic meaning with its exact phase, ordered axes, workspace and target assumptions. The obligation is **forward correspondence**, not completeness of exact synthesis. Semantic acceptance does not imply target execution (#281/#120).
3. **RS / Resource Safety:** quantitative bounds and budgets apply to the actual admitted Core/realization artifact under its selected profile. Count live owners once, allocated ancillas, generated uncomputation, routing, physical SWAPs, measurements/feed-forward where relevant. A restored clean ancilla proves a QS state property, **not** a numerical cost bound. Access exit and `Unit` return do not erase cost (#280).

Current illustrative schemas (not frozen constitutional theorem statements):

```text
Accepted_R(P) -> SemanticSafe_R(P)
Accepted_R(P) AND AdmittedRealization_{R,rho}(P,C,Epr)
  -> Realizes_{R,rho}(C, Meaning_R(P), Epr)
Accepted_R(P) AND AdmittedRealization_{R,rho}(P,C,Epr)
  AND CheckedResourceEvidence_{R,rho}(C,b,Ers)
  -> Cost_{R,rho}(C) <= b
```

A resource claim for **Core alone** may instead use its independently checked Core-cost relation without asserting existence of a target circuit. Neither cost schema permits untrusted producer assertions as certificates. A production path advertising target/quantitative certification must require its actual corresponding evidence, not evade proof via empty premises.

**Independent axes:** exact coefficient paradigm `R` (initially `R_3`, `R_infty`, #309/#339), gate/target realization profile `rho`, and resource cost model. Exact typed base change preserves denotation, not automatic target admission, optimally minimal cost, or cost-certificate transport. No epsilon approximate correspondence discharges edition-2026 constitutional guarantees.

**Specialization:** closed finite instances can have concrete verified cost certificates; a family-level RS guarantee requires an explicit, checked symbolic bound for all admitted parameter choices and provider contracts. Totality and fixed-target feasibility are separate (#127/#161/#162/#164). No single target must handle every instance of an accepted generic family.

**Acceptance boundary:** the frontend, LLM, Rust optimizers, synthesis engines, and caches may only propose unchecked artifacts. Lean/independent checking must validate exact meaning, transformed artifact correspondence, applicable target admission and artifact-bound resource evidence before certification (#136/#309). The three pending broad QS/PR/RS obligations are not automatically discharged by this issue edit. All preexisting implementation checkboxes stay open until independently verified; scope and ledger guarantees remain unchanged.

See #136 (joint boundary), #280 (RS), #281 (PR), #127 (families), #157 (workspace QS), #142 (release gate).

## Problem

A generic definition such as

```text
qft<n>
adder<n>
phase_estimation<n,m>
```

may be a well-typed finite program family.

That does not mean one fixed finite target realizes "the generic program" for arbitrary `n`.

Concrete claims such as:

- exact target realizability;
- physical qubit count;
- gate count/depth;
- target capacity;
- synthesis workspace;
- routing feasibility;

naturally apply after static parameters, basis types, trait/capability choices, and relevant target profile information are instantiated.

If the theorem statements do not say this explicitly, Resource Safety can accidentally conflate:

```text
finite/total family description
```

with

```text
one finite executable target instance.
```

## Proposed theorem boundary

The 0.3.0 specification should treat target/resource theorems as statements over a **closed specialization** or quantify explicitly over admissible substitutions.

Conceptually:

```text
Γs ⊢ p generic and well formed
σ satisfies static constraints
--------------------------------
close(σ,p) = pσ
```

Then target statements apply to `pσ`:

```text
Accepted_now(pσ)
and CheckedRealization_now(pσ, target, C, E)
  -> Realizes_target(C, Meaning_now(pσ), E)

CheckedResourceEvidence_now(pσ, target, C, E, bound)
  -> resource_use_target(C) <= bound
```

Alternatively, a theorem may quantify:

```text
for every admissible finite specialization σ, ...
```

but it must not silently interpret a generic family as one concrete circuit. No premise may be an unchecked producer assertion; #135 binds these schematic judgments to the actual production acceptance gate.

## Static admissibility

The specialization premise should include whatever 0.3.0 ultimately requires:

- natural-number/size constraints;
- basis-type/kind constraints;
- trait/capability resolution;
- finite static evaluation;
- target-domain premises where relevant.

The exact source semantics of the family remains independent of whether every possible specialization fits a chosen target.

## Resource Safety consequence

Resource Safety should distinguish:

1. **computability/totality of the static family**, from
2. **resource function computability for a closed specialization**, from
3. **budget feasibility on a particular finite target**.

These are related but not identical statements.

A family may be total for every finite `n` while no single fixed-capacity target supports all `n`.

## Same-edition family growth and forward PR

The constitutional PR duty is checked correspondence for an admitted realization of a specialization. It does not require complete synthesis over every mathematical object or every possible specialization (#281).

A family-level RS claim may use a symbolic bound such as `Resource(P<n>) <= f(n)` when the language admits and certifies that family. Such an obligation arises under the RS jurisdiction already present in edition 2026; it does not create a new Fundamental Theorem or require an edition change merely because the proof becomes nontrivial.

The Guardian determines the required family/instance obligations. Discharged binding interpretations enter the ledger, and future implementations must preserve them against current acceptance and artifacts.
