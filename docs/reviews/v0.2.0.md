## Contracts and limits

[Machine interfaces](../machine-interface-spec.md) specify the executed-step
roundoff allowance and aggregate identity accounting. The allowance belongs
only to approximate numerical sampling. It is neither a certified error bound
nor exact evidence; normalization never changes the evidence checker. Exhaustive
`run` retains its established unnormalized-ensemble behavior.

Source sharing does not identify different paths, reorder snapshots or bypass
metadata checks. Conflicting text for one label, repeated indices within an
identity, unused/dangling sources and genuine aggregate limit overflow still
reject. The 10-million-unit exact-work budget includes each distinct retained
allocation and all existing semantic work. No transport limit was raised.

[Frontend limits](../frontend-v0.md) and [static-operation limits](../static-operations.md)
explain the distinct scaling constraints. Improving diagnostic attribution does
not remove expansion. Repeated squaring already reduces matrix-power work but
cannot prevent coefficient growth. Omitting transformed-meaning comparison
would weaken the current contract. The [A020-03 continuation](../v0.2.0-backlog.md#a020-03--precision-and-repetition-duplicate-algorithm-bodies)
requires actual-body/count/request binding, phase/axis preservation, independently
checked composition and adversarial tests before production structural sharing.
Those features remain pending in the [0.2.1 plan](../v0.2.1-plan.md).

The [phase-layout proof ledger](../lean-phase-layout-slice.md) now distinguishes
pairing a cyclic basis action with an ordinary value from interpreting it as a
complex operator on an entangled reference system. Existing downstream Lean
names and theorem types remain compatible; the new alias supplies no new rule.
