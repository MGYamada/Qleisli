# Qleisli 0.1.0

Release date: **2026-09-27 (JST)**. License: **Apache-2.0**.
Copyright 2026 Masahiko G. Yamada.

Qleisli's first source release connects a finite quantum language to
independently checked IR and exact, reusable semantic contracts. It implements
the declared finite V01-C1–C6 profile in the
[release milestones](../release-milestones.md). The compiler remains a
prototype; general compiler correctness and the v1 algorithm abstractions
remain open.

The project north star is: **make the language people use to think about
quantum algorithms coincide with the language they use to write programs**.
The next milestone is executable Shor, QPE, and Grover expressed through their
shared mathematical structure and checked component contracts.

## Included in this release

- A finite `.qli` frontend with module resolution, exact type trees,
  linear quantum ownership, explicit effects, product patterns in coherent
  lifts, and classical Boolean expressions.
- Independent raw-IR validation and a bounded reference simulator, including
  observation, classical feedback, and phase-preserving static inverse,
  control, and repetition.
- Exact finite contracts `U E_in = E_out u`, checked isometric encodings,
  sequential/tensor composition, and qualified adjoint/control rules.
- Certified `with_computed` regions that check auxiliary zero return, including
  phase oracles, auxiliary H;H, and simultaneous data/auxiliary X.
- `apply_contract` for substituting implementations under a fixed function
  specification. Immutable evidence survives axis remapping, adjoint,
  coherent control, repetition, and final IR validation.
- Bundled basis, algorithm-routine, transform, and arithmetic definitions;
  executable finite Bell, Grover, QPE, error-correction, and order-finding
  examples; a Rust host example that extracts factors of 15.
- English specifications and contracts, a separate Lean ownership/scope/Kraus
  proof development, and documented contribution and compatibility policies.

Compared with earlier unreleased source snapshots, `true`, `false`, and
`apply_contract` are reserved words. Rename identifiers using those spellings.
The two-argument `with_computed` retains its earlier restricted Z/T rule;
the three-argument certified form has a separate exact semantic check.

## Build and run

Rust **1.85 or later** is required. The Rust crate has no external dependencies.
Check out the release tag, or extract its GitHub source archive:

```sh
git clone --branch v0.1.0 https://github.com/MGYamada/Qleisli.git
cd Qleisli
cargo build --release --offline
cargo run --release --offline --bin qleisli -- check examples/function_contracts
cargo run --release --offline --bin qleisli -- run examples/function_contracts
cargo run --release --offline --example shor15
```

The function-contract example prints `101: 1.000000000000e0`. The finite
Shor host example reports factors 3 and 5 on successful samples, with ideal
success probability 1/2 and an explicit retry probability of 1/2.
This is a fixed N=15 demonstration, not a general Shor implementation.
See the [Lean instructions](../../lean/README.md) for the separately pinned
Lean/Mathlib 4.30.0 development.

Distribution consists of the annotated `v0.1.0` Git tag and a GitHub source
release. A crates.io publication or prebuilt binary distribution is separate.

## Validation

The final local review used macOS and Rust 1.98.1:

- 245 Rust tests passed across all targets; rustfmt and Clippy passed.
- 14 documentation-checker tests and local-reference validation passed.
- 39 exact rational/algebraic example assertions passed.
- Lean built successfully; all 527 project declarations passed the axiom
  audit, using only `propext`, `Classical.choice`, and `Quot.sound`.
- Cargo source packaging and its verification build passed. The package
  includes the license, attribution, bundled sources, examples, and proofs.
- The semantic-contract, function-contract, and Shor host examples ran with
  their documented results.

Local macOS checks exclude one Linux-only CLI test and did not execute Rust
1.85.0. The release CI runs the Rust tests on Linux with both 1.98.1 and 1.85.0,
plus documentation checks and the Lean build/axiom audit. All release-commit
jobs must succeed before its release tag is published. The GitHub release
record supplies the exact commit and CI run.

The [conformance ledger](../specification-status.md) distinguishes these
checks from paper proofs, Lean model theorems, and open Rust proof obligations.

## Supported bounds and remaining work

Exact semantic contracts use at most six public circuit bits and 1,024 flat
steps. Certified computation permits five data bits plus one auxiliary.
Exact arithmetic, work, source-tree, dependency, and execution budgets can
reject inputs before those individual maxima are reached. The
[semantic-contract](../semantic-contracts-v0.1.md) and
[function-contract](../function-contracts-v0.1.md) specifications give the
complete profile and entry/cleanup conditions.

The reference simulator uses floating-point amplitudes. Numerical execution
does not authorize a proof or approximate auxiliary release. General
size/operation parameters, portable evidence loading, observation/approximation
contracts, external backends, and the v1 textbook-structure milestone remain
future work. Tests and the Lean development do not prove the whole Rust
compiler correct or guarantee noisy-hardware behavior.
