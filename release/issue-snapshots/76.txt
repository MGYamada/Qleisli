## Decision

Qleisli keeps three operations distinct:

1. **binding/slot exchange** — not provided for live quantum owners in the 0.3.0 core;
2. **ordered axis/tensor-factor permutation** — an explicit structural operation, named `permute_axes` in specification/examples;
3. **physical quantum SWAP** — the quantum gate meaning of `swap`.

Therefore the unqualified quantum name `swap` is reserved for the physical SWAP unitary.

## Physical SWAP

A quantum call named `swap` denotes the actual two-subsystem SWAP operation under its declared interface, for example conceptually:

```qli
swap(excl a, excl b);
```

It changes the quantum state according to the SWAP unitary. It is not a source-binding exchange.

## Structural permutation

Reordering output/tensor axes without applying the physical SWAP gate is spelled explicitly as a structural operation:

```text
permute_axes
```

Its meaning/evidence must state the exact old/new ordered-axis map.

A backend may realize logical routing using physical swaps when required, but that is an implementation/Physical-Realizability fact and does not change source semantics.

## Binding exchange

Rust-style `mem::swap` for live quantum-containing bindings is not part of the 0.3.0 quantum core.

Ordinary classical values may have ordinary exchange utilities separately; they do not define quantum SWAP semantics.

## Acceptance criteria

- [x] `swap` has one public quantum meaning: the physical SWAP unitary.
- [x] `permute_axes` denotes explicit structural axis reordering with an exact permutation witness.
- [x] No binding-exchange API for live quantum owners is imported from Rust in 0.3.0.
- [x] Optimizers/backends cannot silently identify structural permutation with physical SWAP without checked routing correspondence.
- [x] Diagnostics distinguish binding exchange, axis permutation, and quantum SWAP.

## Compact rule

> **`swap` moves quantum state; `permute_axes` changes representation order; binding exchange is not a quantum primitive.**
