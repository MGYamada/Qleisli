## Release purpose and scope

0.1.1 collects compatible fixes verified while checking the
[user-supplied Claude review of 0.1.0](../reviews/claude-v0.1.0.md):

- Reuse immutable function-contract evidence without repeatedly comparing and
  charging the same source/raw snapshots inside the compiler's frozen cache.
  Preserve full-project validation and independent evidence binding checks.
- Report contract failures at the originating expression, including nested
  branches, and display the first differing exact matrix component. Clarify
  parse-error messages while preserving public error variants.
- Detect numerical auxiliary leakage before certified projection and correct
  a checked dyadic-arithmetic boundary. Numerical alarms do not authorize
  approximate cleanup or replace exact semantic evidence. The diagnostic
  ratio uses scaled coordinates so tiny amplitudes cannot hide material
  relative leakage through squared-weight underflow; stored amplitudes and
  non-finite-weight alarms remain unchanged.
- Add independent exact/numerical circuit comparisons, physical auxiliary
  execution regressions, diagnostic tests, and MSRV Clippy coverage. Make bit
  packing in function-evidence tests explicit for the Rust 1.85 Clippy rules.
- Clarify tuple/bit output order and record the imaginary-v1-first design
  process adopted for the next minor release.

The intended patch preserves public syntax, Rust/IR/evidence APIs, Lean
declarations, ownership/effect rules, phase and axis conventions, capacity
limits, and minimum Rust 1.85 support. No migration is intended. Dependency
versions remain unchanged. Acceptance of previously rejected programs may
improve where redundant compiler bookkeeping exhausted the existing budget.

Public IR removal, shared call IR, new error variants, language forms,
standard APIs, size/operation parameters, and general soundness proofs remain
outside this patch. The existing finite profile and proof limitations in the
[release milestones](../release-milestones.md) still apply.

### Release-candidate checks

- Rust: `cargo fmt --check`, `cargo test --all-targets`, and
  `cargo clippy --all-targets -- -D warnings`. Use a fresh Cargo target directory
  for the final candidate to avoid relying on stale build artifacts.
- Documentation and exact examples: `python3 scripts/test_check_docs.py`,
  `python3 scripts/check_docs.py`,
  `python3 scripts/check_semantic_contract_examples.py`, and `git diff --check`.
- Lean, from `lean/`: `lake build` and
  `lake env lean -DwarningAsError=true Audit.lean`, using the pinned toolchain.
- Documented CLI examples: check and run the ten projects under `examples/`
  (Bell, phase oracle, feedback, Grover, Bernstein–Vazirani, bit-flip code,
  phase estimation, order finding, semantic contracts, and function contracts).
  Run `cargo run --offline --example shor15`; confirm the documented factors,
  success probability, and retry behavior.
- Distribution: inspect `cargo metadata --no-deps --format-version 1 --offline`
  and `cargo package --list --allow-dirty --offline`; verify LICENSE, NOTICE,
  bundled sources, examples, and proofs. Run `cargo package --offline` on the
  clean candidate commit in P011-4 to build and verify the archive, then inspect the GitHub
  source archive's attribution files before publication. A file listing alone
  is not a package verification build.
- CI: the [workflow](../../.github/workflows/ci.yml) must pass on the release
  commit, including the Linux-only CLI test and both Rust toolchains.

## Relationship to 0.2.0 and 1.0

The [pre-0.2.0 prerequisite](../release-milestones.md#pre-v020-imaginary-v1-code)
remains mandatory before 0.2.0 generalization/new-feature implementation and
release: first write initial imaginary Qleisli 1.0 programs for QPE, Grover,
amplitude estimation, Shor, quantum walk, and QSVT, with an index of the required
contracts, capabilities, and open questions. They may be noncompiling drafts.
The corpus is still pending; it is not a prerequisite for this compatible
maintenance release. Executable V1-C1–C5 and general proof obligations retain
their separate completion criteria.
