## Delivered scope

Implement the [fixed-width M1 language forms](../next-minor-spec.md): static
`Op<A>` / `Op<A,m>` parameters and explicit bracket arguments, independent
`Apply` / `Adjoint` / `Controlled` constraints, permutation/phase meanings,
`bind_op`, and inverse, sequential, tensor, controlled, repeated and conjugate
descriptions. These descriptions remove the need to duplicate a helper body
for each operation or provider. Generic bodies must justify access from their
headers; a concrete caller cannot supply undeclared access retrospectively.

The [runnable example](../../examples/operation_contracts/main.qli) substitutes
Z and four T gates in one unchanged client, under the same independently fixed
meaning, returning `11` with probability one. Exact meaning includes phase,
ordered axes and Unit nodes in the basis tree. Quantum ownership remains linear;
descriptions carry no quantum state or captured runtime value.

`FiniteMeaning` and `MeaningEvidence` adapt finite mathematical targets to
canonical existing monomial IR and checked `FunctionEvidence`. Full targets,
implementation IR and immutable source/dependency snapshots remain in the
retained receipt. Static constructors emit the existing `ApplyUnitary` /
`CircuitAction::Contract` vocabulary; derived concrete circuits are compared
exactly with their composed meaning and final IR passes independent checking.
There is no new core IR variant or verifier/evidence acceptance rule. This
revises the earlier selected design's proposed successor action: the existing
core can express the obligation, so extending its acceptance base is unnecessary.

Abstract checking uses disposable non-executable placeholders for operations.
It checks names, types, ownership, declared effects and capabilities, and never
returns a `VerifiedProgram` or issues evidence for an abstract operation.
Parametric three-argument computed equations are deferred until specialization;
each concrete instance must pass the existing exact cleanup check. The two
computed forms and `apply_contract` retain closed name operands and their
different evidence requirements. The two-argument form still accepts only its
existing expanded identity/Z/T body.

The bounded profile remains 0–6 interface bits, 1,024 materialized steps,
10,000,000 exact work units per finite check, 0–4,096 repetitions and at most
256 distinct concrete operation specializations per project. Existing source
depth/tree/work limits apply. Non-generic programs keep their original bounds.
Uninstantiated generics are source-checked; they are not executable artifacts.

## Compatibility and migration

- Rename old source identifiers colliding with `meaning`, `static`, `Op`,
  `requires`, `Apply`, `Adjoint`, `Controlled`, `permutation_by`, `phase_by`,
  `bind_op`, `inverse_op`, `then_op`, `tensor_op`, `controlled_op`, `repeat_op`
  and `conjugate_op`. Old regression fixtures named `meaning` now use
  `specified`, preserving the behavior those tests exercise. The existing
  function-contract example likewise renames `meaning.qli` to
  `specification.qli` and updates its imports; module components are identifiers.
- Public AST/lexer APIs add variants and declaration/call fields. Update
  exhaustive matches for `FnKind::Meaning`, `FnBody::Meaning`, tokens and the
  new `ErrorCode::Capability` / `Contract`; initialize `static_params`,
  `requires` and `static_args` when constructing AST records. Compilation still
  starts from source and does not trust mutable host ASTs.
- JSON version 1 uses its already specified `capability` and `contract`
  categories. Existing successful human/JSON CLI commands and core Rust IR /
  `FunctionEvidence` consumers keep their behavior. There is no portable
  evidence format in this change; X2/X3 remain open.
- Documentation rendering includes complete meaning declarations and access
  constraints. Parsing/documentation does not establish a semantic contract.
- No production dependency, new sealed gate, stdlib public definition, toolchain
  increase or Lean proof change. Lean/Mathlib remain 4.30.0; Physlib is deferred.

adaptive connections, Python distribution, sampling and portable evidence are
separate pending slices. M2 hierarchy/R14, sized algorithms and general Rust
soundness proofs remain open. This version does not satisfy V1-C1–C5.

No v0.1.8 tag, push, hosted release or registry publication is performed by this
implementation task. Exact-commit CI and full release/distribution validation
remain release gates. The v0.1.7 publication and validation record is preserved.
