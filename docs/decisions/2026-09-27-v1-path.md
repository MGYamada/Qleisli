## Static operations and capability representation

Choose **static operation descriptions with separately checked access
evidence** as the semantic model. An operation parameter captures no live
quantum owner. Its immutable identity includes the required meaning, exact
interface/layout, implementation and dependencies. Apply, inverse, controlled
apply and efficient power access are separate judgments on that description.
Application consumes and returns the complete quantum interface; observation
is excluded from this unitary profile.

The existing draft spellings describe different layers:

| Draft spelling | Decision |
| --- | --- |
| `ControlledAccess<U_A>` | A possible surface wrapper for an evidence-bearing description, not a second semantic notion of control. |
| `requires ControlledBinaryPowers(U,m)` | A proposition/constraint discharged by checked access evidence for each required power. |
| `with_binary_powers` | A candidate evidence producer attaching implementations and derivations; it cannot assert a capability unchecked. |

Use constraints on static parameters as the initial specification direction;
dedicated public capability wrapper types are not required for M1. The
[selected grammar and rules](../next-minor-spec.md#grammar-and-resolution)
use square-bracket static parameters, explicit operation arguments and
Apply/Adjoint/Controlled constraints with checked static constructors.
The angle-bracket parameters plus `unitary_op` builders and the square-bracket
static-parameter header `fn f[static n, static U: ...]` are recorded as R02
alternatives, not equivalent accepted grammars. M1 selects square-bracket static parameters; general
operation-returning builders and runtime first-class operations are deferred.

Accept a fixed-width body instantiated with two phase-fixed implementations
and independently checked required access. Reject hidden quantum capture,
incompatible type trees, wrong phase, stale dependencies, and requesting
control/inverse from mere opaque apply access. A control implementation is not
inferred from a mathematical unitarity assertion.

### Control through conjugation

For phase-fixed unitaries `V,W : H(A) -> H(A)` and a distinct control C, let
`C(W) = |0><0| tensor I + |1><1| tensor W`. Then, in operator order,

```text
C(V W V†) = (I_C tensor V) C(W) (I_C tensor V†).
```

The zero sector is `V V† = I`; the one sector is `V W V†`. This proves exact
equality, including phase, and remains true after tensoring an arbitrary
reference identity. Execution applies V† first, then controlled W, then V.
Required access is V, V† and controlled W; controlled V is unnecessary.
Reject a merely isometric V without a suitable unitary extension, an unmatched
inverse, overlapping control/target ownership or unchecked private cleanup.

Thus `R_psi = A R0 A†` needs A/inverse and controlled R0. A computed phase
oracle `C_f† Z_aux C_f` can control only Z while performing the compute and
uncompute unconditionally, provided its zero-entry/exit evidence is retained.
The same rule gives controlled G from controlled reflection and oracle.
This is a selected future derivation rule, not an optimization already performed
by current `qif`, which controls each flattened step. Current behavior remains
valid, albeit potentially more expensive. The [AE cost account](../imaginary-v1/amplitude-estimation.md)
now separates the two constructions.

## Meaning language independent of a gate decomposition

Select a small typed semantic language as an M1 design focus. The first
forms are `permutation_by(f)` and `phase_by(phi)`:

```text
f : A -> A total and bijective       P_f |x> = |f(x)>
phi : A -> Z/8Z total                D_phi |x> = zeta_8^(phi(x)) |x>
```

These are logical meanings, not permission to execute an arbitrary map.
The first profile derives them from bounded basis computations.
[Phase typing](../next-minor-spec.md#meanings-and-binding) uses the three-bit
tree `(Bit,(Bit,Bit))` for exponents modulo eight; no runtime phase type is added. Fix the required meaning independently of the
provider's circuit, then check its equality using bounded dense leaves or the
existing whole-function checker in M1. Preserve exact source type trees, phase,
encodings and dependency snapshots. Reject nonbijective permutations and
phase-equivalent-only implementations. An inverse table or function proves
bijectivity only after its equations are checked.

For M2 introduce semantic primitives for the positive-sign `F_(2^m)` and
phase-fixed controlled powers, with explicit bit order and corresponding
checked schemas. A named primitive in the meaning language is not a new
unchecked physical gate. The mathematical target, circuit realization and
evidence remain different objects. Current `apply_contract` still takes a
separate unitary function as its specification; the research terms also use
circuit-oriented vocabulary. Neither already supplies this sublanguage.

## Three scaling gates and joint IR/evidence design

R14 is necessary, but not the only prerequisite for scalable algorithms:

| Gate | Required design and acceptance evidence | Milestone |
| --- | --- | --- |
| R14: compositional checking | Typed meanings/encodings and shared derivations checked without a whole logical dense operator; bounded leaves, negative binding cases and measured checker costs. | M2 before size generalization |
| R02/R04: hierarchical implementation IR | Shared call definitions, static loops and parameterized families; bind proofs to the exact definition, static arguments, ordered ports, effects and dependencies, not just a flat gate digest. Validate call/loop interfaces, zero-count bodies and transformation witnesses without expanding every call. | Designed with evidence in M1; implemented/validated in M2 |
| R06/R09: circuit synthesis without whole-space tables | Compile a declared total Boolean/arithmetic fragment into reversible X/CNOT/Toffoli circuits with explicit compute/copy/uncompute and exact scratch proofs. Bound generation/checking cost in expression/circuit size, not the size of the complete truth table. | M3 predicate subset; M4 modular arithmetic |

For a noninjective f, synthesize the reversible XOR oracle
`|x,y,0_s> -> |x,y xor f(x),0_s>`, not the invalid in-place map `|x> -> |f(x)>`.
In-place permutations additionally require a checked inverse and whole-space
behavior. No claim of polynomial synthesis for every succinct specification
is made. For Shor, specify add/compare/reduce/uncompute stages, out-of-residue
behavior and modular-power identities.

The present `basis fn`, coherent lift, `Monomial` and computed-function fields
use explicit tables; calls/static transforms expand bodies. These remain the
finite reference path. Retaining a small proof while flattening its entire
implementation is insufficient. R14 and hierarchical IR must be tested
together on nontrivial compositions at multiple widths, with separate proof
size, IR size, generation time, checker work and quantum execution costs.
For the selected families, require polynomial proof/IR size in the declared
width and construction parameters, and checking polynomial in the shared
artifact size and bounded leaf work. This does not imply polynomial execution
in the bit length of a repetition count or efficient synthesis of every function.
Compact `Repeat` does not make executing U many times unit-cost.

`RawOp` and `CircuitAction` are public Rust enums. New variants or changed
fields require MINOR classification and migration: preserve the old finite
format/API through an explicit checked adapter or versioned successor, reject
unsupported nodes, and document exhaustiveness/source changes. Do not silently
reinterpret existing tables or replace meaning checks with hashes.

## Bounded kernel scope and ideal QPE angles

M2 targets a declared finite range of widths and **per-size compositional
checking**, not general symbolic equivalence or a proof of all n. A shared
proof DAG with bounded leaves suffices only after its complete typing,
encoding, resource, entry/release and implementation binding are checked.
Add only the rules needed for the selected programs: associativity with typed
interfaces, rewire composition, compute/uncompute, conjugation, and an explicit
schema instantiation boundary. Existing Lean local equations, including
`compute_uncompute`, are inputs; they are not proofs of a Rust rule checker.

Start schema work with QFT and controlled powers in M2; add predicate/arithmetic
schemas in M3/M4. Each schema needs a fixed identity/version, a Lean theorem
with explicit premises, independently validated static instantiation, and a
binding from its conclusion to actual hierarchical IR. A theorem name, supplied
hash, or arbitrary Lean proposition cannot authorize a certificate. The
[fixed registry import boundary](../hierarchical-ir-spec.md#fixed-schema-import-boundary)
specifies manifest/type checks and actual IR template witnesses. Its implementation,
new schema theorems and Rust correspondence remain open obligations. General proof search and arbitrary equivalence decision procedures
are outside this scope.

Select **ideal exact dyadic phases** `exp(2 pi i j/2^k)` as the M2 QPE direction.
Represent angle expressions symbolically, with canonical modular exponents
and a declared denominator bound; use schemas without whole-matrix products.
Current `Z[zeta_8,1/2]` leaves support only their existing angles: pi/8 needs a
new checked representation or rule. No present QFT4 support is claimed.
The [selected M2 profile](../hierarchical-ir-spec.md#first-qpe-profile-and-exact-angles)
fixes target/precision widths 1–8, dyadic denominator exponent at most eight,
16 live interface bits, graph/work budgets, diagnostics and little-endian order. The ideal QPE
instrument and statistical error remain explicit. Backend approximate synthesis
gets its own operator/instrument error metric and compositional budget; it may
not weaken exact scratch cleanup. Ideal execution is not a hardware guarantee.
