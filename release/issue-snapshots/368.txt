Several common authoring forms, including ones an LLM writes first, produce diagnostics that point at the wrong problem or are malformed. Reproduced on `main` (54fa33a). Each project uses a schema-2 `Qargo.toml` with `edition = "2026"`.

## 1. `adjoint` of an observing function reports a type mismatch, not an effect error

```qli
use std::quantum::init0;
use std::observe::measure_z;

observe fn m(q: Q<Bit>) -> Bit { measure_z(q) }

observe fn main() -> Bit {
    let q = adjoint(m)(measure_z(init0()));
    measure_z(q)
}
```

```text
main.qli:7:21: type_mismatch: type or tuple/size shape mismatch: expected `Bit`, found `Q<Bit>`
```

An endomorphic observing provider gets the correct effect diagnostic ("operation provider's inferred body effect must be Unitary"). The non-endomorphic case should report the effect obligation too, or at least mention it.

## 2. `if` without `else` points at the next line

```qli
    let m = measure_z(q);
    if m { x(excl r); }
    (m, measure_z(r))
```

```text
main.qli:11:5: parse: parse error: expected `else`, found `(`
```

The span is on the following statement. If `else`-less `if` is intentionally unsupported, the diagnostic should point at the `if` and say so, for example suggest `else { () }`.

## 3. Qualified call path in expression position

```qli
observe fn main() -> Bit {
    std::observe::measure_z(init0())
}
```

```text
main.qli:4:8: parse: parse error: expected `}`, found `::`
```

The feature itself is tracked by #65 and #251. This item asks only for a diagnostic that says qualified call paths are unsupported and suggests the corresponding `use`.
