## Superseding primitive/prelude boundary — #167 / #369

The adopted final-0.3.0 cutover in #167 and #369 fixes language primitives as directly available, language-owned unqualified operations. They are not `std::` exports, explicit primitive imports or an implicit `std::prelude` import. In particular, `h`, `measure_z`, `split` and `join` in the earlier candidate discussion below belong to that language boundary; neither this issue nor a future prelude restores retired `std::quantum` paths or grants primitive authority through a library name.

Any future prelude exposes derived stdlib definitions only as ordinary imports/reexports of checked `.qli`, with the same type, ownership, caller-visible effect, access, Meaning and native-checking obligations. Examples include the ordinary `std::state::init0` and `std::gate` gates. Ordinary `std::gate::id` retains its complete Basis parameter and explicit `type(A)` actuals; prelude membership must not infer missing static arguments or turn it into a sealed primitive. This states the already adopted boundary, not an implemented prelude/reexport syntax or a newly selected member list.

The earlier body is preserved below as design history/proposals. Its primitive-import wording and primitive candidate entries are superseded by this boundary. #58 remains open: the derived member list, default availability, explicit mode/opt-out, collision/versioning behavior and implementation/equivalence tests still require the separate work recorded here. This alignment adds no implementation, issue-completion, theorem, guarantee or release credit, and changes none of #167/#369's remaining validation duties.

## Scope

Design work at the **Qleisli 0.3.0 boundary**, requested on 2026-09-30. This records the prelude direction; it does not make implicit imports an implemented API.

Related: #14 design criterion, #32 surface-language normalization, #41 name resolution, #48 Language Reference.

## Problem

Ordinary quantum programs repeatedly spell a collection of individual imports before expressing their algorithm. The current contract requires explicit imports for every library function and has no implicitly opened `std::prelude`.

This boilerplate obscures small textbook examples and adds repetitive work for human and AI authors. Under the project's “when uncertain, follow Rust” policy, a small standard prelude is a natural way to make common names available.

## Preferred direction

Introduce a **`std::prelude`** with a small, documented set of commonly used names, and define its default availability in ordinary source modules.

Prefer a Rust-like default prelude so basic examples need no repetitive import header. Decide an explicit opt-out or equivalent fully explicit mode as part of the name-resolution contract. The exact member set remains to be selected.

Candidate members include common preparation, gates and observation operations such as `init0`, `h`, `x`, `z`, `t`, `cnot` and `measure_z`. Algorithm-specific routines need not all enter the default namespace.

Illustrative proposed program under the default prelude:

```qli
observe fn main() -> (Bit, Bit) {
    let (a, b) = cnot(h(init0()), init0());
    (measure_z(a), measure_z(b))
}
```

The import-free example is a design target, not a claim about current syntax.

## Name-resolution decisions

Coordinate these rules with #41:

1. Specify exactly which names the prelude supplies, and in which modules it is available.
2. Specify precedence among local declarations/bindings, explicit imports and prelude names. Use deterministic resolution with an explicit Rust comparison and diagnostics for ambiguous cases.
3. Keep qualified `std::...` paths available, and define how users opt out or write programs with explicit resolution.
4. Decide how prelude additions are versioned: introducing a name must not silently resolve an existing program to a different declaration.
5. Specify whether the prelude needs dedicated internal resolution or public reexports/import syntax; do not treat unrestricted glob imports as an automatic prerequisite.
6. Keep the bundled `std` identity, visibility, source limits and dependency checking explicit.

## Elaboration and trust boundary

Prelude lookup should resolve to the same already specified library declarations and sealed operations that explicit imports select.

It must introduce no quantum primitive or new verifier rule. Ordinary library definitions remain subject to the same checks as user code; selecting a prelude name does not grant evidence or bypass ownership, effects, phase or clean-return obligations.

## Acceptance

- Basic Bell/preparation/gate/measurement examples lose the repeated import header.
- The prelude and explicitly imported versions resolve to the same declarations and produce equivalent independently verified IR/evidence.
- Tests cover local shadowing, explicit-import conflicts, qualified calls and the chosen opt-out behavior.
- Prelude changes cannot silently alter algorithm meaning through name capture.
- The member list, resolution order, diagnostics and migration are documented in the Language Reference and quick reference.

## Concrete beta implementation contract — 2026-10-19

This records the implementation choices before source changes, under the existing #58 task and adopted QS/PR/RS/EXACT boundaries. These forms remain **unimplemented** at this checkpoint; this is no new constitutional interpretation, primitive admission, guarantee or completion credit.

### Ordinary prelude and resolution

Use a small fixed derived-only prelude:

- `std::gate::{id,x,z,t,cnot}`
- `std::state::init0`

An ordinary, readable `stdlib/src/prelude.qli` will publicly reexport those original declarations:

```qli
#![no_implicit_prelude]

pub use std::gate::{id,x,z,t,cnot};
pub use std::state::init0;
```

The implicit opening denotes those same original canonical DefIds; it is not a forwarding function or an extra implementation/evidence identity. No algorithm is added to std. Bare `h`, `measure_z`, `split`, `join` and the other language primitives are not prelude exports and retain their language-owned behavior. `id[type(A)]` keeps its complete Basis actual; membership never infers a missing static argument.

Resolution is deterministic: original lexical runtime/static binding first; then same-module declaration or explicit import (their existing collisions reject); then the implicit derived prelude; finally a genuinely unbound bare language primitive. Wrong category, moved owner, failed effect/type/access or missing static arguments cannot retry another tier. Existing declarations and explicit imports retain precedence. Prelude members must not collide with bare primitive identities; future additions must pass that compatibility check and cannot capture an already resolved program. Changing an existing selected meaning requires the ordinary versioned breaking-change process.

### Explicit mode, public reexports and qualified references

A module can opt out with the single supported leading header `#![no_implicit_prelude]`. Comments/whitespace may precede it; it must occur once before any import/declaration. This introduces no general attribute/macro facility. Opt-out disables only implicit prelude lookup: bare language primitives, explicit `use std::prelude::...;` and qualified ordinary references still work.

Add transparent `pub use module::item;` and existing brace-group forms, without `as`, glob or relative imports. Public reexports resolve to the original public declaration through the common declaration table. Visibility, public effect, static/Meaning/provider category and dependency identity are checked at that original target; a facade cannot leak private access or same-module effect precision. Explicit duplicate/declaration collisions still reject. Resolve export graphs without source-order dependence under existing work limits; reject unanchored export cycles, while retaining ordinary unused import-only cycles.

Allow root-qualified ordinary declaration references/calls such as `std::gate::x(q)`, including their existing explicit static actuals. Qualified lookup uses the common canonical table and original visibility/category checks, not lexical or primitive fallback. Retired foundation paths and qualified primitive aliases remain rejected. No module/import/visibility operation enters runtime Core.

### Binding, impact and required validation

The fixed prelude is part of the captured canonical std sources/content identity. Load and check it as ordinary source in the common frontend; preserve all original files, spans, dependencies and public-effect checks. The additional bundled module shares the existing file/aggregate/module/work budgets; migrate exact boundary expectations without raising any cap. No ambient manifest switch or independent std selector is introduced.

QS requires unchanged owner, effect, phase, type/axis and reference contracts through the same independently checked IR route. PR and quantitative RS gain no primitive/cost privilege from opening or reexporting a name; source/runtime/target preservation and the broader exact obligations remain separate. Preserve both admitted ordinary-QLV1 guarantees and their current evidence; no new native acceptance rule or Lean axiom is planned.

Compare import-free/explicit/opt-out/qualified forms at the original canonical targets and independently accepted IR/evidence. Complete checked-subject/source digests may legitimately differ with retained source bytes and must not be ignored to manufacture equality. Add small positive/fault cases for shadowing, collisions, missing Basis actuals, primitive separation, private/reexport chains and cycles, original public effects, hidden observation and work limits.
