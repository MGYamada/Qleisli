## Scope and compatibility

This section records the initial compatible IR fix. The later comment extension
and its explicit version exception have their own scope and migration below.

The independent raw-IR verifier must diagnose inputs exceeding its published
[64-level classical-branch limit](../ir-prototype.md). Previously the guard
ran only on a child operation. A chain of 65 branches with empty deepest arms
was therefore accepted; adding an operation to the deepest arm caused rejection.

The verifier now checks depth at each `ClassicalBranch`, before checking its
condition or entering either arm. Both empty and nonempty 65th branches are
rejected with `nested branch exceeds the initial IR depth limit`, whose
operation-index path identifies that branch. Valid 64-level chains remain
accepted. With multiple invalidities, the depth diagnostic may now precede
another error, consistent with the existing diagnostic-order policy.

This repairs erroneous acceptance beyond an already published bound under
the [PATCH exception](../versioning.md#what-compatibility-covers); it does not
introduce a smaller supported capacity. `.qli` grammar, public Rust/Lean APIs,
effects, phase, ownership, cleanup contracts, dependencies and toolchains are
unchanged. Lean/Mathlib remain 4.30.0; Physlib stays deferred. No whole-verifier
or source-to-IR soundness theorem is claimed.

## Reproduction and regression evidence

[`branch_depth_limit_counts_empty_branches_in_both_arms`](../../tests/verify.rs)
failed against the previous implementation because the 65-level empty-arm
fixture returned `VerifiedProgram`. It passes after the fix. Its twelve cases
cover 63/64/65 levels, then/else nesting and empty/nonempty leaves, including
the exact rejection path. The existing 1,000-level rejection case is retained.

[`branch_preflight_checks_both_functions_and_inactive_empty_arms`](../../tests/function_evidence.rs)
covers twelve cases at 31/32/33 levels, both nesting sides and both evidence
inputs. Extraction selects the shallow arm, so the deep arm must be checked
by preflight independently of execution. Accepted cases retain complete
`Q<Unit>` phi ownership and the exact scalar identity. The function-evidence
checker already enforced its separate 32-level bound; no change to that
checker or its accepted profile was needed.

The initial suspicion of recursive destruction during deep-IR rejection was
not confirmed: the existing iterative `RawOp` destructor already handles
that path. The scoped review found the branch-counting defect above; this is
not a claim of a complete evidence-boundary or B019 audit.

## Internal IR reduction and trusted-core boundary

The subsequent 2026-09-28 implementation consolidates legacy `QuantumIf` arm
execution through a private `UnitaryStep` to `CircuitStep` adapter. The common
executor runs primitive monomials and scalar phases in place. Public IR,
verifier acceptance, ownership, phase and execution-step limits are unchanged;
the exact evidence extractor stays independent of the adapter.

The user also adopted the [small trusted-core discipline](../design-philosophy.md#keep-the-trusted-core-small).
Convenience belongs in untrusted desugaring, not in the checker. The
[constructor inventory and migration gates](../interoperability-roadmap.md#ir-reduction-and-the-trusted-boundary)
record raw-only `QuantumIf` and broader `ProtectedUse` forms as compatibility
debt. This step removes a duplicated numeric interpreter, not trusted
verification rules. A smaller versioned core and actual rule removal require
a separately specified MINOR migration.

The additional regression exercises 61 arm configurations against independent
exact extraction, including every primitive, both polarities, empty arms,
scalar phase on `Unit`, composed arms, reversed physical placement and a
coherent reference. It checks exact execution-step boundaries and preservation
of the state-vector allocation. It is a finite differential test, not a
general soundness or foreign-translation proof.

## Desugaring and coefficient-domain documentation

In a further documentation-only follow-up on 2026-09-28, the user requested
explicit definitions and supplied a gate-architecture caution. The
**[desugaring layer](../terminology.md#desugaring-layer)** means meaning-preserving
translation of convenience representations into already specified core
operations, with untrusted IR/evidence for independent checks and no new
primitive meanings or checker rules. Definitions in the design, implementation,
interface, roadmap and operational documents now make this boundary explicit.
The existing post-verification qif runtime adapter is not that desugaring layer.

The [coefficient-domain recommendation](../coefficient-domains.md) records the
risk of assuming one future logical gate set, with primary STAR references and
the `P(π/8)` counterexample to coverage by the current R8 ring. Future domain
type parameters require reviewed arithmetic, interpretation, equality and
evidence binding. Exact, approximate and device/noise claims remain separate;
small leakage never grants exact pure release. The recommendation changes no
Rust API, accepted domain, M1/M2 schema/profile, dependency or proof.

## Rust-style comments and stdlib documentation

The user subsequently requested comments/docstrings, alignment with Rust
conventions, and finally retention of **v0.1.6** after the MINOR requirement
was explained. The [extension specification](../documentation-comments.md)
and [version-policy exception](../versioning.md#version-identity) record the
resulting feature/acceptance changes explicitly. No manifest was moved to 0.2.0.

- Add nested block comments, inner/outer line and block docs, syntactic
  attachment checks and a separate documented-module data API. Existing
  public AST fields and lexer token variants remain unchanged.
- Add `qleisli doc <source-file>` and Markdown rendering without execution or
  a checked-contract claim. Both successful output and errors use the stated
  streams/exit codes; write errors are reported rather than panicking.
- Document all four bundled source modules and twelve public/three private
  definitions in English. Existing `.qli` API contracts and quantum semantics
  remain unchanged; docstrings grant no verification privilege.
- Record migration: doc spellings require supported positions; ordinary line
  comments now end at LF/EOF, and bare CR is rejected in doc text. Old prose can
  use ordinary comment forms; line endings can be converted to LF/CRLF.
