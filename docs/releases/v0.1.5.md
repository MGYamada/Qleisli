- Select the [M0 dossier](../decisions/2026-09-27-v1-path.md): fixed-width M1
  operation/access/meaning interfaces and bounded M2 kernel continuation,
  with a dated scope checkpoint. Complete the selected
  [M1 language specification](../next-minor-spec.md),
  [machine interfaces](../machine-interface-spec.md) and
  [M2 hierarchy/checker profile](../hierarchical-ir-spec.md). G020-1 is complete
  for fixed-width M1; implementations and M2 sized source grammar remain open.
- Use version-independent M0–M5 milestones and continuous maintenance audits;
  strengthen B019-5 so an indefinite no-go does not complete the handoff.
- Record three scaling gates: symbolic checking, hierarchical IR with evidence
  binding, and reversible synthesis without whole-space tables. Select ideal
  dyadic QPE angles and explicit migration for future public IR/special forms.
- Correct conjugation capability/cost reasoning in amplitude estimation and
  Shor indentation; clarify the Physlib investigation's historical scope and
  select a first instrument/CPTP use. Prioritize verifier/kernel proof work.
- Defer Physlib until that bridge uses it: remove the required package and
  five exclusive transitive dependencies, remove its default CI steps, and
  preserve the external audit as optional research. Keep all nine Mathlib
  dependency records and Lean/Mathlib 4.30.0 unchanged.
- Generate [current status and the finite-rule inventory](../current-status.md)
  from one JSON record and manifests; check drift, versions and references.
  Shorten operational guidance and preserve historical evidence/anchors.

These are compatible design/documentation, internal checker and unused-dependency
maintenance changes. Production/research Rust, Qleisli proof declarations,
`.qli` syntax, public APIs, toolchains and supported capacities are unchanged.
Physlib is removed from the required Lean environment; its probe is relocated
to research. No `.qli` migration is required. Direct QuantumInfo experiments
must declare their own external dependency. New JSON/sample/interchange APIs and input byte limits
are future MINOR work. No imaginary algorithm, generalized kernel integration
or new implementation soundness theorem is claimed.

## Specification review corrections

On 2026-09-27, the follow-up review found missing root type information in the
portable format and a mismatch between the controlled-operation block matrix
and low-bit control order. The selected future specifications now require a
validated `root_interface` with exact input/output trees (or null for an untyped
root, which cannot satisfy `--against`), and define control at index c+2x with
an explicit basis permutation for the block-matrix notation. X2/X3 and N2 add
matching/mismatching tree cases, low/high control-bit cases and scalar phase.
Both formats and the M1 constructors remain unimplemented.

Document/reference/generated-status checks, all 19 document-checker regressions
and whitespace checks pass. A standalone exact calculation verifies the
controlled monomial columns and phase exponents against P† diag(I,u) P at target
widths 0–3, including the Unit scalar phase and the two distinct controlled-X
tables. This is a finite mathematical convention check, not an execution of the
future QIRF importer or M1 compiler and not a new general theorem. Rust tests,
Lean build/audit and the unchanged mathematical helper suites are not rerun for
this documentation-only correction. The production and complete-source
candidates are refreshed and content-checked after the record is updated;
the previous extracted research-test scope remains unchanged. Exact-commit CI
and publication remain pending.
