## Historical proposal and completion — original criterion 4 superseded above

## Status

Target: **Qleisli 0.3.0**.

Labels: **important**, **enhancement**.

This is a language/project identity decision, not a change to acceptance semantics.

Related:
- #23 — historical design note already states that the language name is related to Kleisli composition

## Problem

The repository already uses the name **Qleisli**, but its exact etymology and pronunciation are not yet normative.

As the surrounding ecosystem becomes explicit — especially `qargo`, `qrates`, and `qleisliup` — the naming system has acquired a coherent meaning that should be fixed while 0.3.0 is defining what Qleisli is.

Without a short canonical statement, the project can drift into several incompatible explanations:

- “Qleisli” is merely a pun on “quantum Kleisli”;
- the initial `Q` changes the pronunciation;
- the name commits the language to one specific categorical implementation;
- `qargo` / `qrates` are only Rust jokes rather than part of the same design vocabulary.

## Decision

Define the canonical origin of the name as:

> **Qleisli is the Kleisli-style lift of the classical software ecosystem into a quantum ecosystem.**

The spelling is **Q + Kleisli**.

The initial **Q** denotes the move to the quantum world. It is **semantic, not phonetic**.

Therefore:

> **Qleisli is pronounced exactly like Kleisli.**

The spelling change marks the lift; the pronunciation does not change.

This same naming principle is reflected in the surrounding ecosystem:

```text
classical ecosystem        quantum ecosystem

cargo                  ->  qargo
crates                 ->  qrates
```

The `c -> q` transition is intentional: mature classical software-engineering structures are retained where appropriate and lifted across the classical/quantum boundary rather than reinvented merely for novelty.

## Scope and interpretation

“Kleisli-style lift” is the project’s **name origin and design metaphor**.

It does **not**, by itself, require every future Qleisli construct, compiler layer, or theorem to be formalized as a literal Kleisli category or as one particular monad.

Any formal categorical semantics remains a separate technical claim and must be specified and justified independently.

This distinction keeps the name meaningful without letting the etymology accidentally constrain the language theory.

## Canonical wording

A concise normative/documentation form should be approximately:

> **Qleisli** is pronounced exactly like **Kleisli**.  
> The name expresses the project’s central idea: a **Kleisli-style lift of the classical software ecosystem into a quantum ecosystem**.  
> The initial **Q** denotes *quantum*: it changes the semantic world indicated by the spelling, not the pronunciation.

Optionally, ecosystem-facing documentation may add:

> This naming principle is echoed by `cargo -> qargo` and `crates -> qrates`: classical software-engineering structures are lifted into the Qleisli ecosystem where their abstractions remain appropriate.

## Documentation locations

The final wording should be visible at least in:

- [x] the top-level README / project introduction;
- [x] the design-philosophy or language-introduction documentation;
- [x] any canonical pronunciation / naming section used by future website or Book material.

One source should be treated as canonical and the others should point to or reproduce it without semantic drift.

## Acceptance criteria

- [x] Fix the pronunciation of **Qleisli** to be exactly the pronunciation of **Kleisli**.
- [x] Fix the initial **Q** as semantic rather than phonetic.
- [x] Document the canonical name origin: **a Kleisli-style lift of the classical software ecosystem into a quantum ecosystem**.
- [x] Document `cargo -> qargo` and `crates -> qrates` as intentional examples of the same classical-to-quantum naming principle.
- [x] Explicitly state that the etymology does not itself impose a particular categorical/monadic formalization on the language.
- [x] Put the canonical wording in the 0.3.0 normative/project-identity documentation and expose it from the README.

## Core principle

> **The Q changes the world, not the pronunciation.**
