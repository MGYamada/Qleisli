## Problem

Qleisli's strongest current semantic property is that pure meanings are checked **exactly**, including global phase when that phase can become relative under coherent control.

Scalable QFT/QPE and QSVT introduce phases such as `pi/8` and eventually arbitrary synthesized rotations.

If arbitrary floating-point angles are admitted directly into core source semantics, several current invariants become unclear:

- what exact equality means;
- how meanings compose;
- whether controlled versions preserve the intended phase;
- how evidence is checked;
- how synthesis error accumulates;
- whether approximate cleanup can accidentally authorize pure ancilla release.

This boundary should be fixed before arbitrary-angle syntax becomes public.

## Proposed principle

> **Qleisli source meanings are exact. Approximation belongs to an explicitly separate synthesis/backend contract.**

Conceptually:

```text
exact source meaning and exact ideal IR / Meaning
      + actual synthesized target artifact
      ↓
separately checked engineering approximation contract
(metric, finite bound, reference domain and artifact identity)
```

The exact layer may grow its coefficient domains symbolically; it should not silently become floating-point semantics.

## Exact semantic layer

A source operation should denote an exact mathematical object in a declared exact domain.

Examples:

- permutations;
- roots of unity;
- symbolic dyadic phases;
- exact Fourier meanings over supported finite dimensions;
- exact instruments for measurement.

Possible future source phase values may use a canonical symbolic representation, e.g. dyadic turns, rather than floating-point radians.

## Separate engineering approximation layer

If a backend cannot realize the exact meaning, the approximation contract must bind:

- the exact ideal target;
- the actual synthesized implementation;
- an explicit error bound `ε`;
- the metric;
- the admitted input/reference domain;
- the composition rule;
- the actual target gate set and synthesis evidence.

For pure controllable components, a phase-sensitive bound such as

```text
op_norm(U_actual - U_ideal) <= ε
```

is appropriate.

For observations/instruments, use a metric strong enough to cover arbitrary references, e.g. a declared diamond-norm bound.

## Exact cleanup remains exact

Approximation must never weaken ancilla cleanup.

A statement such as

```text
Pr[ancilla != 0] < 1e-12
```

does **not** justify pure release.

Private scratch promised clean must still be returned exactly to the required state/separation condition, or remain part of the output/environment according to an observation/approximation contract.

## Non-goals

This issue does not select:

- a specific hardware gate set;
- a specific synthesis algorithm;
- a physical noise model;
- a fault-tolerance architecture;
- a universal real-number implementation.

## Acceptance criteria

1. QFT/QPE phase conventions remain exact at the source/meaning layer.
2. A `pi/8`-class phase can be represented exactly in the selected symbolic profile.
3. Wrong sign/global phase remains detectable under coherent control.
4. No floating-point equality is used as semantic equality.
5. An approximate backend artifact carries a declared metric and bound.
6. Composition of several approximate operations has a specified conservative budget rule.
7. Instrument approximation is reference-safe by construction of its metric/contract.
8. Sampling error, algorithmic resolution error, and synthesis error are separate fields/concepts.
9. Approximation cannot authorize exact ancilla release.
10. Unsupported exact phases or unsupported approximation contracts fail explicitly.

## Theorem boundary

This separation should align with the project's theorem structure:

- the **Qleisli Soundness Theorem** reasons about the exact checked semantics of the accepted IR/profile;
- constitutional **Physical Realizability** requires the exact correspondence of an admitted realization to its accepted meaning; a separately certified approximate backend contract is an engineering claim and does not discharge edition-2026 PR (EXACT-2026-01, #311).

The source language should not blur that distinction.

## Design intent

The goal is to preserve one of Qleisli's defining advantages:

> **Exact mathematical meaning first; approximation only where implementation genuinely requires it, with an explicit certified error contract.**
