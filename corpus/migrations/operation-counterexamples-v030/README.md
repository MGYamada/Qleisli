# Canonical applications in retained counterexamples

The bounded [Issue #33](https://github.com/MGYamada/Qleisli/issues/33) migration
selects fourteen deliberate semantic faults and one source-rejection client.
Named `adjoint(U, q)` becomes `inverse(U)(q)`; literal
`repeat_static(k, U, q)` becomes `power(U, k)(q)`. Sealed T powers use the exact
ordinary checked `migration_t` wrapper. The provenance validator requires this
fixed translation byte for byte, including the wrapper body. Recorded hashes
alone cannot authorize arbitrary algorithm, count or wrapper changes.

[Preparation](preparation.json), all 29 prepared source files and the first
[predecessor checks](predecessor-checks.json), [derivative checks](checks.json),
[semantic results](semantic-faults.json) and [validation](validation.json)
were saved before source selection. They remain unchanged. The predecessor
paths and hashes bind each original or earlier classical-function snapshot;
original manifests, attribution, licenses and mathematical fault contracts
remain fixed. No previous source snapshot is replaced.

[Selection](counterexamples.json) extends the existing ordered counterexample
migration chain. The fixed basis-to-classical transformation remains separate.
[Current replay](current-replay.json) records actual commands against the
registered derivatives, compiler/kernel/oracle hashes and selected-source
binding. All fourteen faults typecheck and fail the existing independent
small-system mathematical oracle. The measurement inverse retains its
`type_mismatch` refusal. These are bounded numerical mismatch observations,
not a full operator-equivalence or source-preservation theorem.

Rust rejection tests check both frozen originals and current registered
snapshots. Positive and rejection inventories are independently complete;
subsets, duplicate projects and stale migration predecessors still reject.
Integration on the current working inputs passed all 87 positive projects and
both rejection inventories with Rust 1.98.1 and MSRV 1.85.0. The 80 Python
validator regressions include reversed migration order and rehashed changes
to the repetition count or T wrapper. Results are tracked in Issue #33.

Native acceptance rules, capacities, edition and dependency versions are
unchanged. There is no generic QFT work or new constitutional guarantee.
Broader #33 syntax migration and retirement obligations remain open.
