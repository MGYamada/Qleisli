## Status

Core language-design issue for **Qleisli 0.3.0**.

This issue records a semantic fork that should be decided at the 0.3.0 boundary. It does **not** adopt syntax yet.

Related:
- #27 type-theory synthesis
- #44 basis-type polymorphism
- #45 operation capability calculus
- #46 `Meaning` language
- #57 isometry terminology
- #80 Haskell/Qleisli boundary

## Problem

Much of the current design is phrased around endomorphisms:

```text
Op<A>
Meaning<A>
```

but several fundamental quantum operations are naturally typed as arrows between different interfaces:

```text
unitary      A -> B
isometry     A -> B
prepare      Unit -> A
discard/observe variants may also change interface
```

If Qleisli makes `Op<A>` primitive, dimension-changing pure operations and preparation require special cases.

If instead the core is

```text
Op<A, B>
```

then endomorphisms become the special case

```text
Op<A> := Op<A, A>
```

and composition takes the ordinary categorical form

```text
Op<A, B> × Op<B, C> -> Op<A, C>.
```

## Questions to decide

1. Is the semantic core `Op<A>` or `Op<A, B>`?
2. Are unitaries restricted to equal finite dimension while isometries may change dimension?
3. Is basis-state preparation literally an arrow `Unit -> A`?
4. Should `Meaning` mirror the same domain/codomain structure?
5. How do capabilities such as `Apply`, `Adjoint`, and `Controlled` generalize to non-endomorphisms?
6. What is the adjoint type of an isometry `Op<A, B>`?
7. Can controlled application be defined for arbitrary `A -> B`, or only selected classes?
8. How do tensor products type:
   `Op<A,B> × Op<C,D> -> Op<A⊗C, B⊗D>`?
9. How are source-defined functions related to static `Op<A,B>` descriptions?
10. Is `Op<A>` retained as surface sugar for the common endomorphism case?

## Recommended design criterion

Choose the representation that requires the fewest semantic exceptions.

Preparation, isometry, composition, tensoring, and semantic refinement should all be expressible by the same arrow calculus.

## Acceptance criteria

- The Reference gives one normative operator typing judgment.
- Preparation does not require an unrelated special semantic category.
- Sequential and tensor composition have explicit domain/codomain rules.
- Endomorphisms remain ergonomic.
- Capability derivation and `Meaning` refinement remain compatible.
- Exact phase, axis order, ownership, and evidence identity are preserved.
- No new trusted acceptance path is introduced.

## Non-goals

This issue does not decide final spelling, generic syntax, or implementation layout.

## Design intent

Qleisli should decide whether its reusable quantum objects are fundamentally **operators on one space** or **typed morphisms between interfaces** before 0.3.0 freezes the language.
