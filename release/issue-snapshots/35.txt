## Problem

Qleisli already uses destructuring patterns in `let`, coherent `do`, and basis parameters, while future static folds need pattern carries. These should not evolve as separate mini-grammars.

## Proposed direction

Define one recursive `Pattern` grammar, conceptually:

```text
Pattern ::= Ident | _ | (Pattern, Pattern, ...)
```

and reuse it wherever destructuring is semantically valid:
- `let`;
- basis-function parameters;
- coherent `do`;
- `for const ... carry`;
- selected static bindings.

## Important distinction

Pattern structure does **not** change function arity.

```text
f(a,b)
```

remains two arguments, while

```text
f((a,b))
```

is one product argument.

## Decide

- which binder positions allow patterns;
- whether ordinary quantum/runtime function parameters allow destructuring;
- wildcard rules around linear fields;
- duplicate-name rejection;
- interaction with canonical product reassociation;
- diagnostic locations.

## Acceptance

All binder forms that mean "bind components of one value" share one grammar and one shape-checking rule.

## 0.3.0 Rust/Qleisli boundary addendum: wildcard/rest patterns over linear quantum data

As part of the Rust/Qleisli boundary audit, 0.3.0 must explicitly extend the existing wildcard rule to any future Rust-like rest-pattern surface.

The current rule is already correct:

- `_` may discard only classical values in ordinary runtime patterns;
- a live linear/quantum binding cannot be hidden by shadowing.

If Rust-like patterns such as

```rust
Foo { a, .. }
```

or tuple/slice rest syntax are introduced, `..` must **not** become an implicit linear-resource sink.

Required design question:

> **Can every elided field/component be proven classical or otherwise explicitly discharged?**

Acceptance extension:

- [x] any future rest pattern over an aggregate containing live quantum ownership is rejected unless every omitted component is non-linear/classical or explicitly consumed by a separate language rule;
- [x] rest-pattern syntax never implies discard, reset, release, or measurement;
- [x] diagnostics identify the hidden linear field/component;
- [x] this rule is documented as an intentional divergence from ordinary Rust pattern ergonomics.
