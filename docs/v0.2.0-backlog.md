# v0.2.0 issue backlog

**Started 2026-09-28 at the user's request; current development stays at 0.1.8.**
Collect problems to consider when selecting 0.2.0, especially friction in
LLM-authored `.qli`. These are candidates, not adopted syntax or a promise to
ship every item. [M0–M5](v0x-roadmap.md) and existing evidence gates still govern
dependencies. Active implementation state stays in [current status](current-status.md).

## How to maintain this backlog

When writing examples or implementing features exposes friction, add or refine
an entry here in the same change. Reuse stable IDs; merge related observations.
Keep minimal `.qli` attempts and semantic counterexamples in the source corpus
when practical. Mark untested suggestions as hypotheses, not reproduced bugs.
For each entry retain the date/version, source or design evidence, author burden,
candidate direction, acceptance experiment, checker/dependencies and migration
impact. On resolution, link the actual implementation and tests; do not delete
the observation or infer completion from a shorter program alone.

The first review should examine **A020-01–03** together: register layout and
sharing one algorithm body. A020-04–06 are narrower authoring improvements;
A020-07 is a QPE dependency and A020-08 supplies evaluation across all entries.
This is an investigation order, not an implementation schedule.

## Candidates

### A020-01 — Product layout still leaks into composition

**Observed, 0.1.8.** [The rejected call](../tests/fixtures/qli_authoring/rejected/product_association.qli)
and [working adapter](../tests/fixtures/qli_authoring/accepted/product_reassociation.qli)
show manual split/join work around QFT. Flat tuple sugar removes punctuation,
but left, right and balanced trees remain different interfaces.
Investigate register views, aliases or explicit layout adapters without choosing
syntax yet. **Acceptance:** compose QFT and arithmetic clients without hand-written
tree rebuilding at each call; compare against existing adapters, including
entangled inputs, leaf order and zero-width owners. Specify migration and
translation to existing ownership operations; never silently permute axes.

**Reopened design question, user request 2026-09-28:** reassess whether spelling
`(Bit,Bit,Bit)` as the exact type `((Bit,Bit),Bit)` is the right language design
at all. Do not assume left association is the target merely because it matches
the current AST. Mathematical reassociation does not select a unique source
representation, ownership interface or bit encoding.

Compare left-associated sugar, right-associated sugar, and a genuinely flat
source-level n-ary product whose lowering can still use the existing binary
core. Also decide how explicit nested products differ from flat products and
whether any reassociation is explicit or implicit. These are alternatives to
evaluate, not adopted notation or new trusted rules.

Use the same QFT, arithmetic and meaning-contract clients to compare natural
LLM-authored signatures/patterns, required adapters and diagnostic repairs.
Check field/axis order, phase under control, entangled inputs, Unit factors,
linear ownership, and the distinction between `Q<(A,B)>` and `(Q<A>,Q<B>)`.
Include the current right-associated `phase_by` exponent result in migration
experiments. Before selecting a replacement, document source/public-AST/IR
compatibility, meaning-preserving lowering and semantic regressions. Until a
new decision is adopted, 0.1.8's left-folding rule remains implemented behavior.

### A020-02 — One QPE body across target types

**Observed, 0.1.8; explicitly future work.** [Bit-target QPE](../examples/operation_algorithms/estimation.qli)
cannot serve [four-bit order finding](../examples/order_finding/estimation.qli);
[type parameters reject](../tests/fixtures/qli_authoring/rejected/basis_type_parameter.qli).
Investigate bounded type instantiation separately from size generalization.
**Acceptance:** one checked source body serves both target types and multiple
operations, retains output/reference correlations and rejects missing access.
Specify substitution, termination/work limits, source locations and evidence
identity. Decide definition-time versus instance-time guarantees explicitly;
the [finite-template/R14 question](qli-authoring-feedback.md#finite-templates-and-the-r14-ordering-question)
remains open. A finite experiment does not establish scalable checking or V1-C2.

### A020-03 — Precision and repetition duplicate algorithm bodies

**Observed, 0.1.8; explicitly future work.** [Static naturals reject](../tests/fixtures/qli_authoring/rejected/static_nat.qli),
while [phase2/phase3](../examples/operation_algorithms/estimation.qli) and
[amplify_once/amplify_twice](../examples/operation_algorithms/amplification.qli)
duplicate structure. Investigate bounded size/iteration templates.
**Acceptance:** a shared body instantiates at declared supported values, including
zero repetition where meaningful; reject invalid sizes and excessive expansion
with located diagnostics. Preserve exact types, effects, axes and evidence.
Size generalization still depends on [R14 and hierarchical checking](v0x-roadmap.md#cross-release-prerequisite-symbolic-contract-checking);
moving a finite-only slice earlier requires an explicit design decision. A020-07
also constrains QPE precision; increasing limits alone is insufficient.

The [iterative QPE continuation](../examples/iterative_phase_estimation/iterative.qli)
provides another executable instance: three manual rounds at the same Bit
interface. It strengthens the reproduction for A020-02/03 without resolving them.

### A020-04 — Sealed gates need wrappers as static providers

**Observed, 0.1.8.** [Passing `h` rejects](../tests/fixtures/qli_authoring/rejected/sealed_provider.qli);
[ordinary wrappers](../examples/operation_algorithms/gates.qli) are the workaround.
Investigate uniform access to eligible sealed operations. **Acceptance:** compare
direct providers with wrappers under application, inverse and coherent control;
reject measurement, wrong interfaces and unavailable capabilities. Keep phase
and existing [static-access rules](static-operations.md); unitarity alone grants
no implementation access. Review resolution and reserved-name compatibility.

### A020-05 — Same-typed results conceal algorithmic roles

**Observed, 0.1.8; proposed remedy untested.** [Swapped teleportation messages](../tests/fixtures/qli_authoring/faults/teleport_swapped_message.qli)
compile because both are `CBit`. QPE also relies on positional bit weights.
Investigate named results or role-bearing interfaces and documentation.
**Acceptance:** express message roles and bit order in reusable interfaces;
measure whether authored clients make fewer swaps, while preserving every
message branch and [reference-sensitive tests](../tests/qli_corpus.rs).
Names alone need not reject wrong algorithms. Any new structure must lower to
existing products/classical values with an explicit source/result-API migration.

### A020-06 — Valid cleanup evidence is difficult to discover

**Observed, 0.1.8.** [Two-argument H H cleanup rejects](../tests/fixtures/qli_authoring/rejected/auxiliary_hh.qli),
but [the explicit logical-contract form succeeds](../tests/fixtures/qli_authoring/accepted/auxiliary_hh.qli).
Investigate actionable diagnostics and small copyable contract examples first.
**Acceptance:** guide a failing author to the supported evidence-bearing form,
and test both a repaired program and a false cleanup claim. Retain existing
[exact cleanup checking](semantic-contracts-v0.1.md); scope, names and approximate
simulation are not zero-return evidence. Keep CLI/JSON diagnostics compatible.

**0.1.8 progress:** the restricted-body diagnostic now names the explicit
contract form and requires both owners. [Repair tests](../tests/repair_diagnostics.rs)
check the known H H repair and reject false cleanup. The
[curated replay](../tests/fixtures/authoring_sessions/cleanup-repair/session.json)
records before/after messages; improvement for unfamiliar authors is still
unmeasured. New proof inference or wider acceptance is not part of this fix.

### A020-07 — More QPE precision needs an angle and evidence profile

**Design constraint; no new source experiment in this entry.** The
[QPE prerequisites](imaginary-v1/requirements.md#scaling-prerequisite-for-r14)
explain why a four-bit exact QFT needs a π/8 controlled phase beyond the current
gate profile. A size parameter alone cannot supply it. **Acceptance:** implement
and validate the selected [dyadic profile](hierarchical-ir-spec.md), retaining
exact phase, actual-circuit binding and reference-sensitive QPE results; diagnose
unsupported precision. Keep ideal angles, approximation error and device noise
separate. Link the existing M2 gates rather than inventing a second checker plan.

### A020-08 — Measure LLM authoring and repair, not just compilation

**Evaluation gap.** The [authoring report](qli-authoring-feedback.md) has finite
reproductions, not a controlled LLM benchmark. **Acceptance:** retain task,
model/version, supplied reference/context, untouched first source, diagnostics,
repair attempts and semantic results. Compare the same tasks/context policy
before and after a change; report first-pass and repaired results separately.
Include held-out composition tasks, reference/phase checks and intentional
type-correct faults. A candidate should remove an author obligation, not merely
reduce line count; author identity never changes the verifier's rules.

**0.1.8 progress:** [three saved sessions](../tests/fixtures/authoring_sessions/README.md)
now retain initial source, hashes, actual outputs and revisions. One informed
new-source attempt and two curated repair replays have distinct labels.
Integrity checks run in CI. Controlled before/after model comparison and
held-out task evaluation remain open; these records establish a baseline only.
