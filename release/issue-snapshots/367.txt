## Problem

Running `cargo test --no-fail-fast` on `main` (54fa33a) without `QLEISLI_KERNEL` gives 464 passed, 686 failed and 52 ignored. Nearly all failures are the same missing-checker error:

```text
select the matching Lean checker with --lean-kernel=PATH or QLEISLI_KERNEL
```

Kernel-dependent tests are gated inconsistently:

- Some are `#[ignore]` (for example `hierarchical_execution`, `qft_hierarchy`, `sized_corpus`).
- Others call `expect("select …")` or `unwrap()` and panic (for example `kernel()` in `src/frontend/specialize/raw/preservation.rs`, and many integration tests).
- The crate-level doctest (`src/lib.rs`, `import_openqasm3` + `sim::run_closed`) fails with `InvalidIr("kernel: select …")`.

`lib.rs` correctly says the library builds and documents without Lean. However, `cargo test` is uniformly red for a contributor without a native kernel, so real regressions in the kernel-independent tests cannot be distinguished. `cargo test --doc` also fails for downstream users.

## Proposal

Gating tests is not a verification fallback; acceptance still requires the kernel.

- Use one shared gate for kernel-dependent tests: either a compile-time cfg set by `build.rs` when `QLEISLI_KERNEL` is present, or a runtime skip helper that reports the reason.
- Mark the crate doctest `no_run`, or gate it the same way.
- In the CI job that builds the native kernel, assert that zero kernel-gated tests were skipped, so the gate cannot silently hide coverage.

## Acceptance criteria

- [x] Without a kernel, `cargo test` passes or skips every kernel-dependent test with an explicit reason, and runs every kernel-independent test.
- [x] With a kernel, CI fails if any kernel-gated test was skipped.
- [x] `cargo test --doc` passes without a kernel.
